# Japanese Web Typography Skill

## 目的

日本語Webサイトのテキストについて、単純な文字数ではなく「意味」「日本語の自然さ」「デザイン」「レスポンシブ表示」を基準に、自然で読みやすい改行・折り返しへ調整する。

このSkillは以下の2用途で使用する。

1. **新規HP制作時**：初回実装から自然な改行設計を行う。
2. **既存HP修正時**：不自然な改行、孤立した助詞、固有名詞・文節・語尾の分断、スマホ表示崩れなどを検出し修正する。
3. **最終Visual QA時**：コードだけで判断せず、実際の画面・スクリーンショットを確認し、意味途中の折り返しが残っていないことを確認する。

---

## 使用トリガー

以下の依頼・状況ではこのSkillを使用する。

- 「日本語の改行を直して」
- 「スマホで見出しが変な位置で折れる」
- 「HPの文字組みを整えて」
- 「見出しの改行位置を自然にして」
- 「助詞だけ次の行になるのを直して」
- 「店舗名や商品名が途中で切れている」
- 「レスポンシブ時の日本語表示を調整して」
- 日本語HPを新規制作する
- Hero / H1 / H2 / H3 / CTA / カードタイトルを実装する
- 「カード内コピーの改行が気になる」と指摘された
- 「ここは改行しない方がよいか」と相談された
- デザインコピーが「から」「こと」「たい」などの途中で分断されている
- 最終提出前のVisual QAを行う

---

## 完了条件

次をすべて満たすまで完了扱いにしない。

- 日本語として自然な位置で折り返されている
- 助詞・句読点・記号だけが孤立していない
- 店舗名・ブランド名・商品名などの固有名詞が不自然に分断されていない
- PCだけでなくスマートフォンでも自然に読める
- 文字がコンテナからはみ出していない
- 重要見出しが過剰に4〜5行以上になっていない
- 不要な `<br>` の乱用がない
- 「から」「こと」「たい」など文節・活用語尾の途中で不自然に分断されていない
- Heroだけでなく、カード・Feature・Service・About・Conceptなど大きなデザインコピーを全件確認している
- 375px / 390px / 430pxとDesktop幅で実画面またはスクリーンショットを確認している
- コード上の正しさだけでなく、実画面として自然である
- Visual QAで問題が見つかった場合、修正→再確認を繰り返し、問題を残したまま完了しない

# 1. 基本原則

1. **文字数ではなく意味のまとまりで改行する。**
2. 本文は原則としてブラウザの自然改行を利用する。
3. Hero・大型見出し・CTAなど、デザイン上の意図が明確な箇所のみ手動改行を検討する。
4. 不自然な改行をCSSだけで無理に隠さず、必要なら文章そのものを自然に短くする。
5. PCよりもスマートフォンでの見え方を必ず確認する。
6. Heroだけでなく、カードタイトル・カード内キャッチコピー・Feature見出し・Service見出し・About/Conceptの大型コピーも「デザインコピー」として扱う。
7. デザインコピーでブラウザ任せの折り返しが日本語として不自然になる場合、その状態を許容しない。

---

# 2. 改行位置の優先順位

改行位置は以下の順で判断する。

1. 意味の大きな区切り
2. 文節の区切り
3. 並列関係
4. コピーとしてのリズム
5. デザイン上のバランス

### 良い例

```text
地域に愛される、
温かいお店を目指して
```

```text
旬の食材を使った
こだわりの料理
```

```text
いつもの日常に、
少しだけ特別な時間を。
```

---

# 3. 禁止する不自然な改行

以下のような改行を避ける。

### 助詞の孤立

NG:

```text
地域の皆様
に愛されるお店
```

```text
こだわりの料理
をお楽しみください
```

Better:

```text
地域の皆様に
愛されるお店
```

```text
こだわりの料理を
お楽しみください
```

### 1〜2文字だけの孤立

NG:

```text
想いを込めた料
理
```

```text
特別な時間
を
```

OK:

```text
想いを込めた
料理
```

```text
特別な時間を
あなたに
```

---

# 4. 助詞・短語の孤立防止

次の語を単独で新しい行の先頭に置かないようにする。

- は
- が
- を
- に
- の
- と
- へ
- で
- も
- や
- から
- まで
- より

短い助動詞や接続語についても、前後の意味を見て孤立を避ける。

特にデザインコピーでは、次のような語の途中・直前直後で不自然に分断しない。

- から
- こと
- たい
- ない
- れる / られる
- です / ます
- という
- ため
- よう

例：`夢中になれるこ / と。`、`つくりた / い。`、`チームか / ら、` のような分断は禁止する。

---

# 5. 日本語の禁則処理

以下の文字を新しい行の先頭に置かない。

```text
、 。 ， ． ！ ？ : ; ） ］ 】 》 〉 」 』
```

以下の開始記号を行末に残さない。

```text
（ ［ 【 《 〈 「 『
```

ブラウザ標準の日本語禁則処理を壊すような `word-break: break-all` は、日本語本文では原則使用しない。

---

# 6. 固有名詞の分断禁止

以下は可能な限り同一の意味単位として保持する。

- 店舗名
- 会社名
- ブランド名
- 人名
- 商品名
- メニュー名
- 地名
- URL
- 電話番号
- 金額
- 日付
- 数値＋単位
- 英単語・英語ブランド名

NG:

```text
SANGL
IER COFFEE
```

許容例（ブランド設計上意図がある場合のみ）:

```text
SANGLIER
COFFEE
```

固有名詞を保持するために短い範囲へ `white-space: nowrap` を使用してよいが、モバイルではみ出さないことを必ず確認する。

---


# 7. カード・デザインコピーのルール

Hero以外でも、以下は通常本文ではなく「デザインコピー」として扱う。

- カードタイトル
- カード内キャッチコピー
- Feature見出し
- Service見出し
- Aboutの大型コピー
- Conceptコピー
- CTAの大きなメッセージ

これらはブラウザ任せの自然折り返しだけに依存せず、**意味単位で読めること**を優先する。

### NG例

```text
一つのチームか
ら、文化の輪へ。
```

```text
誰もが輝ける場所
を、光と音でつくりた
い。
```

```text
上手になる前に、
夢中になれるこ
と。
```

### OK例

```text
一つのチームから、
文化の輪へ。
```

```text
誰もが輝ける場所を、
光と音でつくりたい。
```

```text
上手になる前に、
夢中になれること。
```

カード幅やフォントサイズによって自然に成立しない場合は、文章・幅・フォントサイズ・letter-spacing・line-height・意味単位ラッパーの順で調整し、最後の手段として意図的改行を使用する。

---

# 8. 意味単位の保持

単語だけでなく、**短い文節・意味のまとまり**も必要に応じて同じ行に保持する。

保持候補の例:

```text
ご都合のよい方法で
一つのチームから、
誰もが輝ける場所を、
光と音でつくりたい。
夢中になれること。
```

必要な場合は、短い意味単位を `span` で包み、分断を防止してよい。

```html
<p class="card-copy">
  <span class="keep-phrase">一つのチームから、</span>
  <span class="keep-phrase">文化の輪へ。</span>
</p>
```

```css
.keep-phrase {
  display: inline-block;
}
```

ただし、長い文章全体を `inline-block` や `nowrap` で固定しない。小さい画面で横にはみ出す場合は別の方法を選ぶ。

---

# 9. Hero・H1のルール

Heroコピーは意味・リズム・視認性を優先する。

- 原則2〜3行以内
- モバイルで4〜5行以上になる場合は、コピーそのものを短くすることを検討する
- 助詞だけの行を作らない
- 重要語を途中で分断しない
- 1行目と2行目の意味の重さを意識する

例:

```text
いつもの毎日に、
ちょっと特別なひとときを。
```

```text
地元の食材と、
心を込めた料理。
```

```text
大切な人と過ごす、
特別な時間。
```

---

# 10. H2・H3・セクション見出し

- できるだけ短くする
- 長い場合は意味単位で2行に分ける
- 1〜2文字だけ次行へ落とさない
- サブタイトル（英字など）がある場合、見出し本文と役割を混同しない

例:

```text
地域の皆様に愛される
お店を目指して
```

---

# 11. 本文

本文では原則として手動 `<br>` を入れない。

代わりに以下で可読性を確保する。

- 一文を長くしすぎない
- 2〜4文程度で段落を分ける
- テキストコンテナの最大幅を設定する
- line-height を適切に取る
- ブラウザの自然改行を活用する

---

# 12. HTML実装ルール

意図的な改行が必要な重要見出しは、`<br>` の乱用より意味単位のラッパーを優先する。

```html
<h1>
  <span class="heading-line">地域に愛される、</span>
  <span class="heading-line">温かいお店を目指して</span>
</h1>
```

```css
.heading-line {
  display: block;
}
```

ただし、この実装でもモバイルで不自然になる場合はブレークポイント別に調整する。

---

# 13. PCとMobileで改行位置を変える場合

必要な場合のみレスポンシブ専用クラスを使用する。

```html
<h1>
  地域に愛される、<br class="desktop-break">
  温かいお店を目指して
</h1>
```

```css
.desktop-break {
  display: inline;
}

@media (max-width: 768px) {
  .desktop-break {
    display: none;
  }
}
```

レスポンシブ用 `<br>` の大量使用は禁止する。

---

# 14. 推奨CSS

日本語本文・見出しでは、必要に応じて以下を検討する。

```css
body {
  word-break: normal;
  overflow-wrap: anywhere;
  line-break: strict;
}

h1,
h2,
h3 {
  word-break: normal;
  line-break: strict;
}
```

見出しでは、対応ブラウザを確認した上で次も利用可能。

```css
h1,
h2,
h3 {
  text-wrap: balance;
}
```

`text-wrap: balance` のみに依存せず、Heroなど重要コピーは実画面で確認する。

---

# 15. `white-space: nowrap` の使用

短い固有名詞や数値＋単位など、分断すると意味が壊れる範囲に限って使用する。

```html
<span class="nowrap">SANGLIER COFFEE</span>
```

```css
.nowrap {
  white-space: nowrap;
}
```

長文全体には使用しない。

---

# 16. テキスト幅で調整する

不自然な行長を `<br>` で調整する前に、コンテナ幅を検討する。

```css
.text-content {
  max-width: 720px;
}

.hero-copy {
  max-width: 900px;
}
```

Mobileでは必要に応じて100%へ戻す。

```css
@media (max-width: 768px) {
  .hero-copy {
    max-width: 100%;
  }
}
```

---

# 17. 文字数の参考値

絶対ルールではなく目安として使用する。

### Hero H1

- PC：1行 12〜24文字程度
- Mobile：1行 8〜16文字程度

### Section Heading

- 8〜20文字程度

### Card Title

- 8〜18文字程度

### CTA

- 10〜24文字程度

本文は文字数ではなく、段落・最大幅・行間で調整する。

# 18. レスポンシブ確認幅

最低限、以下を確認する。

- 375px
- 390px
- 430px
- 768px
- 1024px
- 1440px

特にスマートフォン中心のHPでは375〜430pxを重点確認する。

---

# 19. 既存HPの修正手順

ユーザーから「改行を修正して」「スマホで文字が変」と依頼された場合は以下の順で対応する。

1. 対象ページを確認する
2. Hero / H1 / H2 / H3 / CTA / Card / 店舗名 / 商品名を重点確認する
3. 不自然な折り返しを一覧化する
4. 原因を分類する
   - コピーが長すぎる
   - 固定 `<br>` が原因
   - コンテナ幅が狭い
   - font-size が大きすぎる
   - `word-break` が不適切
   - 固有名詞保護がない
   - PC専用改行がMobileへ残っている
5. 最小限の変更で修正する
6. 375px / 390px / 430px / Tablet / Desktopで実画面またはスクリーンショットを確認する
7. Heroだけでなくカード・Feature・Service・About・Conceptのデザインコピーを全件確認する
8. 新たな不自然な折り返しが発生していないか確認する
9. 問題があれば修正→再表示→再確認を繰り返す

---

# 20. 修正の優先順位

既存HPの改行問題では以下の順で修正を試みる。

1. コピーそのものを自然に短くする
2. コンテナ幅を調整する
3. font-size を調整する
4. letter-spacing / line-height を調整する
5. CSSの日本語折り返し設定を調整する
6. 固有名詞・短い意味単位に限定して `nowrap` / `inline-block` 等を適用する
7. Hero・カードなど必要箇所だけ意味単位の `span` を使用する
8. 必要な場合のみ意図的な改行を設定する
9. 最後の手段としてデバイス別 `<br>` を使用する

手動 `<br>` の追加を最初の解決策にしない。

---

# 21. コピー変更の判断

現在の文章では自然な改行が作れない場合、意味を維持した上でWeb向けに短くすることができる。

元文章:

```text
地域のお客様に長年愛され続けている店舗でありたいと考えています。
```

Web用例:

```text
地域に愛される、
そんなお店であり続けたい。
```

ただし以下は勝手に変更しない。

- ユーザー指定の正式キャッチコピー
- 店舗名
- 会社名
- 商品名
- 法的表記
- 営業時間・住所・価格などの事実情報

変更が必要な場合は、意味を変えない範囲で修正する。

# 23. AIの最終判断ルール

改行判断は必ず以下の順で行う。

1. 日本語として自然か
2. 意味のまとまりになっているか
3. 固有名詞を壊していないか
4. 助詞・記号が孤立していないか
5. Mobileで読みやすいか
6. PCで読みやすいか
7. デザインとして美しいか
8. HTML/CSSを過度に固定していないか

**文字数だけを根拠に改行しない。**

---

# 24. 実行時の出力

改行修正を依頼された場合、内部では問題箇所と修正理由を確認するが、ユーザーが説明を求めていない場合は不要な長文説明をせず、実際の修正を優先する。

コード編集が可能な環境では、指摘だけで終わらず対象ファイルを修正し、レスポンシブ表示を確認する。

---

# 25. Visual QAループ

コード編集だけで完了判定しない。

日本語改行の品質は、**実際に描画された画面**を見て判定する。

最低限、次の流れを実行する。

```text
実装
↓
対象ページを表示
↓
375px / 390px / 430px / Tablet / Desktopで確認
↓
Hero・見出し・カード・CTA・大型コピーを目視
↓
不自然な改行を検出
↓
修正
↓
再表示
↓
再度スクリーンショットまたは実画面確認
↓
問題がなくなるまで繰り返す
```

特に以下の状態は、HTML/CSS上エラーがなくてもQA不合格とする。

- `チームか / ら`
- `なれるこ / と`
- `つくりた / い`
- `場所 / を`
- 1〜2文字だけ次行に残る
- カードごとに改行リズムが大きく不揃い
- 同じ画面内で一部カードだけ4〜5行になる
- Desktopでは自然だがMobileで意味途中に折れる
- Mobileでは自然だがDesktopの狭いカードで意味途中に折れる

**「コードとして正しい」ではなく、「日本語として自然に読める」が合格条件。**

---

# 26. 提出前の最終ゲート

HPを顧客・確認者へ提出する前に、以下を必須ゲートとする。

1. Japanese Web Typography Skillを読み込んだ
2. Hero / H1 / H2 / H3を確認した
3. 全カードのタイトル・キャッチコピーを確認した
4. CTAを確認した
5. 固有名詞を確認した
6. 375px / 390px / 430pxを確認した
7. Tablet / Desktopを確認した
8. 実画面またはスクリーンショットを目視した
9. 修正後の再確認を行った
10. 日本語として違和感のある改行が残っていない

1つでも未確認なら提出完了としない。
